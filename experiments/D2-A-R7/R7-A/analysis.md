## 统一单位

D2-A共同物理RD网格是32个距离格 × 130个周期Doppler格，即每CPI名义4,160个CUT。4×零填充仅是候选频率过采样，必须映射回同一130点周期物理网格；不能把每CPI分母放大成16,640。

R7工具将dense detector的阈值CUT超越率、一个CPI至少出现一个超越的概率、每CPI超越CUT数，以及每独立H0场景随机抽取一个CUT所得的独立伯努利统计分开保存。稀疏单候选学生没有逐CUT分数图，其`Pfa_cell`为`NOT_APPLICABLE`，另报`Pfa_CPI`和稀疏输出率。没有阈值的软教师响应不计算Pd/Pfa。

历史口径逐阶段记录于[`history_pfa_audit.csv`](history_pfa_audit.csv)。D1学生和多数R5/R6方法输出单一CPI级presence分数；D2-A早期检测器每幅RD图只取一个全局最大值，因此主工作点是`Pfa_CPI`。D2-A-E001另记录`Pfa_CUT`，它是由CPI最大分数阈值诱导的密集CUT超越比例，不是单独校准的低虚警逐CUT工作点，也没有`1e-6`证据。不同历史统计单位不能换算或合并排名。

## 实际资源预检

运行命令：

```bash
python scripts/benchmark_d2a_r7_evaluation.py \
  --scenes 32 --batch-size 2 \
  --output experiments/D2-A-R7/R7-A/metrics.json
```

在Linux Python 3.13.5、NumPy 2.1.3、12个CPU线程可见的当前shell中，以D2-A分离目标配置逐批生成32个H0场景，并用NumPy B3计算原生RD图。测得生成约129.8 scenes/s，评分约4,285.8 scenes/s或17.83M CUT/s；最大一批返回数组约1.00 MB，进程峰值RSS约137 MB。未写入IQ/RD磁盘缓存。当前shell没有PyTorch，因此本次只是CPU资源预检，未运行GPU训练或GPU评分。

按该小样本生成吞吐线性外推，2,995,731个独立场景约需6.41小时；所有4,160个固定CUT同时达到95% Bonferroni置信、零事件上界不高于`1e-6`约需11,328,997个独立H0场景，仅生成约24.2小时。两者均是单条件、单次生成的粗略资源估算，不包括独立阈值校准、重复条件、失败重跑、H1评价和模型推理，也不保证长期吞吐恒定。资源尚不足以批准正式样本预算。

预检输出中的`benchmark_only.pfa_cell`使用同一小批次中位数临时阈值，仅是代码计时负载，不是校准结果或性能证据。实际记录标记`scientific_metrics=NOT_EVALUATED`。

## 统计边界

- 在一个独立H0场景中，4,160个CUT存在相关性。全网格池化比率先作描述；场景簇bootstrap只在非零事件时计算，零事件不产生全零bootstrap区间。
- 每个独立场景预先均匀选择一个CUT，用于跨场景平均Pfa的精确二项上界。零事件、95%单侧上界达到`1e-6`需要2,995,731个独立场景。
- 对每个固定CUT另报跨场景分布；要求95%家族置信所有4,160个CUT均低于`1e-6`时，零事件至少需11,328,997个独立场景。该门比平均Pfa目标更严格。
- 校准分位数样本量和验证样本量需要分别规划。没有足够的独立极端尾部样本，不用ROC外推或理论门限替代。
