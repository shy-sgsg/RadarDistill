# Codex 研究任务执行协议

本协议与 AGENTS.md 配合使用。在仓库科研文件中，`docs/RESEARCH_CHARTER.md` 是最高层级指导；动态阶段以 `docs/CURRENT_STATUS.md` 和 `docs/RESEARCH_ROADMAP.md` 为准；阶段指标和冻结门以对应冻结的实验 protocol 为准。开始任何有科研意义的任务时，必须首先读取当前提交中的研究总纲，不能只按近期任务列表或历史对话机械执行。

历史阶段门约束其原实验和结论，不会自动禁止提出有独立证据的新假设。新假设须单独说明问题、传统基线、数据边界、预算、指标和停止门；若证据冲突于旧计划，记录影响并提出路线修订。

## 研究总纲优先与修订审批

开始科研任务时，先从当前 Git 提交读取 `docs/RESEARCH_CHARTER.md`，理解研究主题、总体目标、核心科学问题、主要研究内容、总体研究思路、长期技术路线、成功标准和创新性边界；随后再阅读当前状态、路线图、假设登记表及相关实验报告。任务对齐必须说明任务如何服务于总纲中的目标和科学问题，以及它对整体路线判断的影响。

**不得自行修改 `docs/RESEARCH_CHARTER.md`。** 对该文件任何正文或版本记录的修改，包括只为同步最新进展而修改，都必须先向用户提交问题、证据、拟议改动和对现有研究的影响，取得用户明确批准后才可执行。批准后的修改必须保留版本、日期和变更记录，并同步相关动态文件。用户未批准时，总纲保持不变。

算法实现、阶段排序和具体实验方案可以在 `CURRENT_STATUS.md`、`RESEARCH_ROADMAP.md`、`decisions.md` 等动态文件中依据证据调整，但调整必须仍符合当前总纲。动态路线调整权限不构成修改总纲的授权。若证据提示总纲本身需要调整，记录证据和建议并提交用户讨论；不得隐瞒新证据，也不得继续开展已被证明无价值或其有效性受该证据影响的任务。可以暂停受影响的任务，并继续独立且符合当前总纲的工作。

## 开始任务前必须阅读

1. docs/RESEARCH_CHARTER.md
2. docs/CURRENT_STATUS.md
3. docs/RESEARCH_ROADMAP.md
4. docs/research/ASSUMPTION_REGISTER.md
5. 与当前任务有关的阶段报告、实验 protocol、decisions.md 和配置。

检查当前 Git 分支、提交、跟踪文件修改和未跟踪用户数据。历史对话不能替代检查当前文件、指标与运行环境。对已有数据只读复核时，不复制、改名或覆盖原件。

## 研究主线对齐

每项有科研意义的任务在 docs/task_alignments/ 下记录简短对齐；普通小修可将此记录写入提交说明或任务日志。记录至少回答：

1. 服务于哪项长期研究目标？
2. 对应哪个科学问题和登记假设？
3. 可检查的现有证据是什么？
4. 为什么现在值得优先做？
5. 完成后会改变哪项研究判断？
6. 是否符合总纲；若偏离，是否只是经证据支持的路线调整？
7. 有哪些更简单或价值更高的替代方案？
8. 成功与失败分别意味着什么？
9. 预先停止条件是什么？

根据回答直接继续正常、已批准的小范围工作；不因例行实现暂停等待用户确认。若需要改变核心研究使命，或路线调整会改变冻结门、盲测数据含义或对外承诺，先给出证据和有界替代方案并取得用户批准。假设失败时提出修订，不机械执行旧计划。

## 实验执行

- 先写问题、可辨识条件、假设、传统基线、数据切分、预算、指标和停止门，再写模型代码或生成盲测。
- 真值、教师硬标签、教师软响应、学生预测分开保存。教师不得覆盖真值。
- 训练、开发、校准和最终测试按独立种子/样本定义；架构选择用过的测试集不得再次称为盲测。
- 复数相位和频率按周期定义误差；报告样本数、种子、统计不确定性和适用边界。
- 使用 CUDA 训练的实验必须先检查实际 CUDA 设备；禁止静默 CPU 回退。控制显存，训练模型按序运行，OOM 先降 microbatch 并保持协议中的有效 batch 与更新预算。
- 任何速度主张必须基于同硬件、同输入边界和完整前后处理链；学生前向耗时不等于整链成本。
- 不以代码可运行、损失下降或通过一个窄测试代替科研验收；未运行实验不得写成已完成。

## 工程与 Git

- 只改当前任务所需的代码、配置和文档；先检查工作区，保留未提交用户数据。
- 每个完成的工作包建立小而清晰的提交；仅暂存审阅过的路径。训练缓存、大型可重建数据和外部生产源码包默认不加入 Git。
- 提交前检查差异、文件大小、配置/结果记录和实际运行证据；没有当前任务的明确授权时不推送或重写共享分支历史。
- 研究代码与生产 GMTI 处理链隔离；无明确证据和批准不修改生产处理。
- 发现旧报告、总纲和当前证据冲突时，记录冲突和影响；保留冻结历史结果，在动态状态文件更新现状。

## 完成与审查

科研任务完成时同步需要更新的指标、分析、进展和决策记录。分别做工程正确性、实验科学性和研究主线审查，并给出 CONTINUE、REFINE、REDIRECT 或 STOP。说明证据、统计范围、资源、未决事项与唯一下一项优先任务。

提交阶段审查材料时，必须使用 `docs/templates/CHATGPT_REVIEW_REQUEST.md`，并以该模板中的以下要求作为汇报开头：

> 请首先读取本次Git提交对应版本的 `docs/RESEARCH_CHARTER.md`，理解RadarDistill的整体研究主题、研究目标、研究内容、科学问题和技术路线，然后结合这些内容审查本阶段的代码、实验、数据和研究结论。

材料必须提供本次 Git SHA、工作区状态、总纲路径及该提交对应的版本、总体目标和科学问题映射、实验 protocol/config、代码入口和实际结果、阶段审查报告、对整体研究方向的影响及下一步建议。不得把计划或未运行内容写成结果。
