# ChatGPT 阶段审查协议

本文件供未来独立 ChatGPT 审查会话读取。审查者不会自动知道仓库、历史对话或本项目规则；发起人必须随审查请求提供当前提交和指定文件。阶段主张以 RESEARCH_CHARTER.md 和冻结 protocol 为准，不能因旧计划写过某路线就默认继续。

## 审查输入

至少提供：

- Git 提交 SHA 和工作树差异；
- docs/RESEARCH_CHARTER.md、CURRENT_STATUS.md、RESEARCH_ROADMAP.md、research/ASSUMPTION_REGISTER.md；
- 实验 protocol/config、代码入口、训练日志、环境/硬件记录；
- 分层 metrics、逐样本统计或可复现评估命令；
- 相关历史阶段报告和 decisions.md。

若缺少完成判断所需的输入，明确列出缺失证据，不把计划、日志摘要或单个截图视为完整结果。

## 第一层：工程审查

核对信号和物理模型、输入输出边界、数据生成和标签、教师/学生分离、训练与评估实现、周期参数误差、随机性、代码入口、依赖、复现命令、资源约束和真实推理成本。检查异常路径、泄漏、静默 CPU 回退和工作区中不应提交的大文件。

输出：工程正确性结论；发现及影响等级；可复核代码/命令/文件；未能验证事项。

## 第二层：实验科学性审查

核对问题、可证伪假设、可辨识条件、传统基线强度、公平对照、样本/场景独立性、训练预算和种子、模型选择、阈值/盲测冻结、指标和统计区间、保护指标、负结果及结论边界。检查多策略/多指标选择是否造成选择偏差，是否出现事后改门或把教师输出当真值。

输出：实验设计与分析是否支撑每条主张；主要偏差风险及其量化影响；哪些结论仅为探索性。

## 第三层：研究主线审查

判断该阶段是否推进总纲中的最终检测和参数估计；是否为精度或完整成本优势提供证据；是否过度优化传统中间模块；是否遗漏可辨识性、教师可靠度或任务冲突；现有假设是否已被否定；继续路线是否仍值得做。阶段门通过不自动意味着旧路线仍是最有价值的下一步。

输出：总纲一致性；现路线的科研价值；需要保留/撤销/修订的假设；适用范围。

## 第四层：战略调整建议

比较至少当前路线和一个最小替代方案。建议要有可验证证据、预期信息价值、成本、依赖和停止条件。不得仅为保持阶段编号而要求继续；也不得因一次负结果就外推否定所有学习方法。

最终选择且只选择一个主判断：

- **CONTINUE：** 冻结门通过，现路线仍最有价值。
- **REFINE：** 目标有效，但需要一个有界、可验证的修正。
- **REDIRECT：** 证据支持转向另一项可证伪路线。
- **STOP：** 当前路线已达到预设停止条件或缺乏足够研究价值。

## 固定审查交付格式

1. 工程正确性结论。
2. 实验科学性结论。
3. 研究主线一致性结论。
4. 创新性与论文价值判断。
5. 总判断：CONTINUE / REFINE / REDIRECT / STOP 及证据。
6. 下一步唯一优先任务、最小方案、改变路线所需证据与停止条件。
7. 证据缺口和结论适用范围。
