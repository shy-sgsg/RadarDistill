# ChatGPT 阶段审查协议

本文件供未来独立 ChatGPT 审查会话读取。审查者不会自动知道仓库、历史对话或本项目规则；发起人必须随审查请求提供当前提交和指定文件。

## 审查的第一步：先读研究总纲

任何阶段审查的第一项工作，都是读取审查请求所列 Git 提交对应版本的 `docs/RESEARCH_CHARTER.md`。先理解 RadarDistill 的整体研究主题、总体目标、主要研究内容、核心科学问题、总体研究思路和长期技术路线，再阅读阶段状态、路线图、假设登记、实验协议及阶段结果。不能用当前工作树里不同提交的总纲代替，也不能仅凭阶段任务列表或本次指标作出方向判断。

如果无法访问所列提交中的总纲，必须明确指出缺失，并在取得对应版本文本前暂停最终阶段判断；不得假定总纲内容或将阶段门通过当作路线正确的替代证据。

阶段主张以该提交的研究总纲及冻结 protocol 为准。历史阶段门约束其原实验结论，但不自动要求继续已经失去价值的路线；动态路线可以根据证据调整，研究总纲正文不可由审查者或执行者自行改写。

## 审查请求的提交时机与阶段推进

审查请求应在用户界定的整项授权任务/研究路线全部目标完成后一次性提交。若范围包含连续多个研究阶段（例如一条多阶段研究计划），应在该范围内的目标完成后再提交一份综合请求，不能把内部阶段拆成多个提前起草或重复提交的请求；阶段内的运行记录、指标和内部阶段报告可以随着工作推进而更新。

缺少外部 ChatGPT 审查默认不阻塞已经授权且满足冻结 protocol 前置门的后续阶段。如果冻结 protocol 或用户明确把独立审查/批准设为某一阶段的前置条件，则该条件仍然有效：暂停依赖它的工作，同时继续不受影响且已获授权的工作。审查回复不是普通工作包的完成条件。

## 审查输入

至少提供：

- Git 提交 SHA 和工作树差异；
- docs/RESEARCH_CHARTER.md、CURRENT_STATUS.md、RESEARCH_ROADMAP.md、research/ASSUMPTION_REGISTER.md；
- 实验 protocol/config、代码入口、训练日志、环境/硬件记录；
- 分层 metrics、逐样本统计或可复现评估命令；
- 相关历史阶段报告和 decisions.md。

若缺少完成判断所需的输入，明确列出缺失证据，不把计划、日志摘要或单个截图视为完整结果。

## 第一层：工程审查

核对信号和物理模型、输入输出边界、数据生成和标签、教师/学生分离、训练与评估实现、周期参数误差、随机性、代码入口、依赖、复现命令、资源约束和真实推理成本。检查异常路径、泄漏、静默 CPU 回退和工作区中不应提交的大文件。

输出：工程正确性结论；发现及影响等级；可复核代码/命令/文件；未能验证事项。

## 第二层：实验科学性审查

核对问题、可证伪假设、可辨识条件、传统基线强度、公平对照、样本/场景独立性、训练预算和种子、模型选择、阈值/盲测冻结、指标和统计区间、保护指标、负结果及结论边界。检查多策略/多指标选择是否造成选择偏差，是否出现事后改门或把教师输出当真值。

涉及学习模型时，还须检查参数量、optimizer updates、每次更新样本数、训练集遍历/独立样本暴露、学习率计划、训练与验证曲线、计算成本和继续/停止准则。若验证仍在改善，不能把低预算结果解释为模型容量或架构上限；固定场景重复训练与在线新场景训练是不同实验。对教师相关阶段，分别评价教师任务能力、软/硬知识质量与学生教学收益，并检查匹配 truth-only、必要的 truth-assisted 对照和知识来源/泄漏。

输出：实验设计与分析是否支撑每条主张；主要偏差风险及其量化影响；哪些结论仅为探索性。

## 第三层：研究主线审查

对照已读总纲，判断本阶段是否推进总体研究目标及最终检测、参数估计或完整处理成本评价；本阶段研究问题本身是否仍值得研究；当前技术路线是否合理；是否过度优化传统中间模块；是否遗漏可辨识性、教师可靠度或任务冲突；哪些研究假设已获支持、被否定或仍未决；是否存在更有价值且可验证的替代方向；是否需要调整长期研究思路。阶段门通过不自动证明研究方向正确，也不自动意味着现路线仍是最有价值的下一步。

对学生路线须结合训练充分性、模型容量和架构归纳偏置作判断；对知识迁移路线须辨别“教师做得更好”与“教师知识让学生最终任务更好”是否被独立验证。

输出：总纲一致性；对总体研究目标的实际贡献；科学问题的研究价值；现路线的合理性与替代方向；需要保留、撤销或修订的假设；长期思路是否需要调整及其证据；适用范围。

## 第四层：战略调整建议

主动判断现有方向是否仍值得继续。若证据表明当前研究问题或路线价值不足，必须提出证据驱动的调整建议；若建议保持现路线，也须说明其相对最小替代方案的预期信息价值。比较当前路线和至少一个有实际价值的最小替代方案，说明可验证证据、成本、依赖和停止条件。不得仅为保持阶段编号而要求继续，也不得因一次负结果就外推否定所有学习方法。建议修改研究总纲时，只能提出具体建议和影响分析，不得把建议当作已批准变更。

最终选择且只选择一个主判断：

- **CONTINUE：** 冻结门通过，现路线仍最有价值。
- **REFINE：** 目标有效，但需要一个有界、可验证的修正。
- **REDIRECT：** 证据支持转向另一项可证伪路线。
- **STOP：** 当前路线已达到预设停止条件或缺乏足够研究价值。

## 固定审查交付格式

1. 审查基准：Git SHA、工作区差异、已读取的 `docs/RESEARCH_CHARTER.md` 版本。
2. 工程正确性结论。
3. 实验科学性结论。
4. 总体研究目标和研究主线贡献；科学问题价值、当前路线及替代方向。
5. 创新性与论文价值判断；现有假设的支持、证伪或未决状态。
6. 长期研究思路是否需要调整及依据；总判断：CONTINUE / REFINE / REDIRECT / STOP。
7. 下一步唯一优先任务、最小可证伪方案、改变路线所需证据与停止条件。
8. 证据缺口和结论适用范围。
