# D2-A-R6 研究路线对齐

## R6-A 前置接口测试记录（2026-10-29）

实现流式接口的测试在 G0 前使用两个预注册种子各生成了一个确定性场景，并在重复测试时重新生成：H0 calibration seed `1208000000`、H1 development seed `1248000000`。测试只检查 IQ 和真值数组形状及 ID 是否不同，没有调用任何检测器、查看 IQ 或标签数值，也没有保存场景或用于模型、阈值和方案选择。这与协议“G0 通过后才生成数据”的执行顺序不符；必须在 R6-A 的 preflight、阶段报告和审查材料中披露。工程测试现改用独立的 `2000000000` 系列种子。由于没有观察科研指标或依据样本调整方案，当前继续实现并在 G0 审计中核查分割和本记录；不得把这一偏差隐去。

## 总纲映射

- **研究主题与目标：** 沿RadarDistill v1.3总纲，通过物理真值和经审查的传统方法知识训练任务级GMTI学生；以可靠检测、连续参数估计和完整处理链成本评价学习/混合系统。
- **核心科学问题：** Q1/Q2 教师知识是否改善学生最终任务；Q3/Q4 表征、容量和优化如何影响检测与估计；Q6 困难杂波下的联合任务质量；Q7/Q8 传统与学习模块如何公平组合；Q9/Q10 教师质量、教学信号和学生能力如何匹配。
- **成功边界：** 不预设AI优于传统方法；固定虚警、Pd、参数与联合任务保护必须同时报告。R6-A/B都是开发证据，不是final blind或系统级 `1e-6` 认证。

## 当前问题与证据

R5-A的Medium容量在复用开发数据上提高了C2/C3 joint success，但其C3 H0 Pfa仍为0.18896。R5-B TFAS的C3 Pfa为0.15186且困难条件任务退化，故停止该候选而不外推否定全部非CNN结构。R5-C独立审查确认教师任务知识有局部证据，但指出C3 partial-overlap / 0 dB定位率仅约4.1%，所以先运行T0–T3受保护教学pilot。固定阈值跨条件失稳、C3检测和候选参数估计哪个构成主要瓶颈仍未由同场景新数据区分。

## 优先与阶段依赖

1. **P0：** 冻结的R5-C T0–T3已经完成；按其阶段审查结论，当前教师内容分支停止，不把G4通过解释为教师全域可靠。
2. **P1：** R6-A建立新场景同输入检测/参数估计基线；R6-B在独立H0上诊断0.05/0.01/0.001并只运行一个由开发证据预选的候选分支。
3. **P2–P6：** 再按单因素推进容量、训练/数据预算、D/P/J联合模型、少数机制代表架构、端到端混合链和有证据的教师协作。

R6设计可以与R5-C CPU数据生成及分析并行；R6 CUDA推理/训练等待R5-C的学生训练释放GPU。R6不等待R5-D机制研究，但不改变R5-C冻结设置。新数据与协议在R5-C运行后仍保持独立。

## 可证伪假设与下一步

- **H-R6-DET-001：** 当前C3固定阈值虚警异常主要由条件间分数分布/尺度迁移引起，且条件内存在足够区分度。R6-A使用新H0 calibration与H1 development分层评分；R6-A H0 verification不参与R6-B分支选择。若条件ROC本身低，则该假设不获支持，优先检查表征和H0覆盖。
- **H-R6-JOINT-001：** 在匹配数据、主干容量和更新预算下，检测—参数联合信息交换能在不恶化C3 Pfa的条件下提高最终joint success。R6-D先测共享多任务J1和一个有界软候选双向J2；只有R6-A/B识别出相关瓶颈后才启动科学pilot。

## 证据优先级与备选解释

当前优先路线是先建立公平基线和低虚警统计证据，再投入更大模型或更复杂交互。备选解释包括H0条件分布确实变化、学生表示缺乏可分证据、候选/参数估计错误主导joint loss、容量或训练暴露不足，以及教师监督内容错误。R6-A拆分actual/correct/oracle candidate误差，R6-B只选一个受约束干预，以避免在同一开发结果上搜索模型和阈值。

若R6-A表明困难场景条件ROC已差，停止纯分数归一化方向；若R6-B候选改善Pfa却损害Pd/参数/joint保护则停止该候选。若R6-D的小样本正确性或显存门失败，停止该具体结构；不外推否定所有联合模型。任何路线改变均记录触发证据、影响和停止条件，保持研究总纲v1.3不变。

## 2026-10-29：R6-A执行准备与batch约束

- **当前状态：** R6-A共享输入评估器、可恢复的紧凑预测输出、正式汇总入口和17项定向测试已实现；G0尚未执行，注册的R6-A场景数据尚未生成。代码提交推送后运行G0，再依协议顺序生成三组数据。
- **公平性：** 保持R6-A的 `chunk_size=16`（仅评估流式分块）和R6-B已冻结的有效训练batch64不变。R5-C历史batch不改。新训练协议可将batch作为有界、预注册、各比较组匹配的实验因素；若扩大batch会改变有效batch、optimizer更新或数据暴露而破坏可比性，则保持原值。
- **重采样复现：** R6-A原协议规定2,000次base-scene bootstrap但未指定随机种子；在任何正式数据生成前补充固定seed `2026102901`，同时更新config，保证阶段指标可复现。
- **资源检查：** 当前CUDA设备为RTX 3050 Laptop GPU；检查时约3.0 GiB显存空闲。桌面与一个独立GMTI应用仍占少量显存，实际每split空闲显存及R6-A峰值将在环境记录中留档；实验不并行训练模型。
