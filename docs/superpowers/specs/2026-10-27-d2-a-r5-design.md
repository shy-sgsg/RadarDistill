# D2-A-R5 设计说明

**版本：** 1.0
**日期：** 2026-10-27
**批准范围：** 用户已明确批准研究总纲 v1.3、R5 分阶段研究路线与实际运行；本文不改变已冻结实验的 protocol 或结果。

## 研究目标和边界

R5 服务于《物理模型与渐进式知识蒸馏驱动的高效雷达动目标检测及参数估计方法研究》：寻找适合三通道复数 GMTI 观测的学生结构，测清训练预算和模型容量的影响，并检验教师知识是否能改善最终检测与连续参数估计。R5 不是独立 CFAR 或教师竞赛。

保持 D2-A 的三通道、PRF=1300 Hz、N=130、32 距离单元、静止杂波和已冻结 A/B/C/D 可辨识边界。不得修改旧协议、旧指标、旧结果或生产 GMTI 链。D 精确同流形条件只作不可辨识边界参考。

## 理论判断与可证伪问题

1. E003 每步使用 32 个 H0/H1 场景对，51,200 对训练样本对应 1,600 updates，故只有一次固定训练集遍历。旧 S0/S2 结果是有限预算 pilot，不能单独确定充分训练性能或架构上限。
2. 训练集重复遍历检验优化/收敛；在线增加独立场景检验数据覆盖；二者必须分开。
3. 增大 `TaskStudent` 的主干宽度可以检验有限表示容量，但无法单独证明所有架构的上限。首轮只比较 Small 与 Medium，并维持层数、dilation、输出头和任务损失不变。
4. 普通 TCN 有长时间感受野但没有显式频率变换或复数旋转等变性。首个非 CNN pilot 采用沿慢时间与距离轴分解的轻量注意力，输入仍为三通道原始复 IQ；避免对 4,160 个时空 token 做全局二次复杂度注意力。
5. 教师能力和教学有效性分开。现有 R3/T001 固定阈值资格失败不自动否定某种软知识；每种 K1–K5 知识都需独立审计可观测性、任务信息量、教师错误和泄漏。

## 路线决策

### R5-A：训练充分性和容量

- 从头训练 seed 101 的 S0 与 E003 S2，使用相同 51,200 对训练场景、相同初始化/顺序/损失/优化器和 CUDA FP32。
- 主要预算 6,400 updates，即固定训练集 4 次遍历；旧 E003 的 1,600-update 曲线只作历史参照，不与新余弦学习率计划的检查点混称为独立 1-epoch 复现。
- 仅在预注册验证趋势继续改善时，使用连续 optimizer/scheduler 状态把两臂都延长到 12,800 updates；不重置 AdamW。
- 之后比较 Small width=32 与 Medium width=96（实际参数量分别约 13,383 与 82,887），第一轮只改变主干宽度。只有训练/验证曲线提供容量瓶颈证据时才考虑 Large。

### R5-B：非 CNN 架构

调研 CNN/TCN、雷达时频 Transformer、复数网络、状态空间模型、深度展开和物理前端加学习器。唯一首选实现为 Temporal-Frequency Attention Student：原始复 IQ 实值视图作输入，以慢时间轴注意力建模 Doppler 相干序列、距离轴注意力建模空间关系；按轴分解注意力，避免全局 token 注意力爆显存。只在单元、过拟合和 CUDA 显存预检通过后，与参数量匹配的 CNN 做一个 seed pilot。物理模型驱动展开仅做适用性/算子设计，不自动启动第二条大规模训练支路。

### R5-C：教学内容和时机

先审计教师候选知识：K0 真值；K1 完整 RD 软响应；K2 教师 IQ 自主定位的局部响应；K3 连续 Doppler 响应/似然/不确定性；K4 物理一致性知识；K5 仅依赖可观测数据的可靠性权重。真值窗口辅助监督必须单列为真值辅助对照，不得称作教师知识。

教师质量前门通过后，才比较 T0 真值、T1 真值+完整响应、T2 真值+任务相关教师知识、T3 真值+与 T2 匹配的真值辅助监督。所有臂同架构、初始化、样本、预算和任务损失。只有某一知识形式显示任务收益后才研究教学时机与 2×2 容量×KD；若知识质量或学生基础学习失败，对应分支停止。

### R5-D：知识吸收机制

在有效知识通过内容 pilot 后，以独立物理干预测量公共相位、频移、跨通道相干、目标/杂波强度与教师/学生四类正确性。梯度只作诊断；没有干预支持时，机制结论标为相关或未决，不写成因果。

## 统一评价

报告 Pd/Pfa、ROC/AUC、各条件 Pfa 及冻结阈值、距离与圆周 Doppler 误差、joint success、训练/推理参数与成本。joint success 定义为检出、距离误差不超过 1 cell、圆周 Doppler 误差不超过 20 Hz；漏检按失败计。对检测使用独立 H0 calibration 设阈值并在独立 H0 verification 报告；所有 H1 分层并按 `base_scene_id` 配对 bootstrap。不得把旧开发集称作 blind；最终模型和选择冻结后才生成新盲测。

## 资源与执行

RTX 3050 Laptop 4 GiB，依次训练，每次只让一个模型驻留 CUDA。先 FP32；按 16→8→4 microbatch 处理 OOM，同时保持有效 batch 与更新数；4 仍 OOM 则停止对应运行，不切 CPU、不悄悄改科学预算。缓存按场景分片落 CPU 磁盘，不缓存整套样本于 GPU。记录 CUDA 环境、显存峰值、检查点、模型/优化器/调度器/RNG 状态、累计更新和数据游标。阶段后按本阶段 manifest 清理可重建数据，保留高价值审计与结果，最终项目不超过 20 GiB。
