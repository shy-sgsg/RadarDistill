# D2-A-R5 执行计划

## Phase 0：治理、研究路线和预注册

- 建立 R5 设计/计划、任务对齐、架构调研、容量/教师研究说明和 R5-A protocol/config。
- 按本次授权修订 `docs/RESEARCH_CHARTER.md` v1.3；同步状态、路线图、假设登记、决策、进度和 README。不得改冻结实验协议/指标/结果。
- 校验数据/训练 seed、磁盘容量、CUDA 设备和配置约束；提交并推送 Phase 0 小提交。

## Phase 1：R5-A 训练充分性

- 扩展独立 R5 runner，支持 51,200 对固定训练场景循环采样、共同 batch plan、6400 更新和每 400 更新验证。
- TDD：计划复用与 split 防泄漏、有效 batch OOM 梯度累积、严格 CUDA 禁 CPU、检查点完整恢复、指标/训练日志。
- 运行小样本过拟合测试及数据/模型 preflight；通过后按 S0→S2 顺序使用 CUDA FP32 训练 seed 101。
- 检查 6400 更新趋势；只有 protocol 条件满足才连续状态延长到 12,800。报告训练/验证 loss 与任务指标。
- phase review 后 commit/push，不触碰 E003 归档。

## Phase 2：Small/Medium 容量

- width 32 对 width 96；预先报告参数、显存和每步成本，仅改变 width。
- 同数据、seed、更新数、初始化机制、loss 和评价规则。按任务曲线区分欠拟合、过拟合、优化与表示瓶颈。
- 若 Medium 无有意义任务收益或保护门失败，停止 Large；若容量瓶颈清晰，才设计 Large 小 pilot。

## Phase 3：一个非 CNN pilot

- 实现慢时间/距离轴分解 Temporal-Frequency Attention Student，保留 raw-IQ 输入；匹配 CNN 参数规模。
- 单元测试、脉冲维度输入检查、16 样本小集过拟合、CUDA 显存预检；按顺序训练一个 seed。
- 对比相同数据暴露/更新预算和合理训练曲线；失败保留依据，不扩展第二种架构。
- 深度展开先完成物理算子/可辨识性设计审查。

## Phase 4：教师知识质量

- 对 R3/T001 冻结教师、B3/T1、适用的 K1/K2/K3/K4/K5 逐一做独立知识质量审计。
- 记录可观测输入、H0/H1 表现、任务相关信息、教师错误、标签泄漏和可靠性；不得重标旧资格。
- 只有至少一个知识形式通过其质量门，才开始 Phase 5 对应臂。

## Phase 5：教学内容 pilot

- 固定 Phase 2/3 选中的学生，在同样初始化、样本、预算与主任务 loss 下比较 T0–T3。
- 蒸馏监督不覆盖 K0 真值；teacher-local 和 truth-window 明确分开。
- 有限候选、bootstrap 和保护指标；没有正向收益即停止教学时机搜索。

## Phase 6：教学时机和机制

- 仅对 Phase 5 通过的知识形式比较预注册 P0/P1/P2 时机。
- 用新独立样本做受控相位/频移/通道相干/强度干预；机制结果与最终任务增益分别报告。
- 若只有损失变化或相关性而无任务/干预证据，标为未支持或未决。

## Phase 7：阶段审查与交付

- 完成阶段指标、曲线、报告、环境/资源记录、假设状态和下一步唯一优先任务。
- 按 ChatGPT Review Protocol 生成含当前 SHA 与总纲版本的审查请求。
- 执行受授权测试、差异和路径审计，确认 20 GiB 项目限制；每个完成的工作包提交到 main 并推送。

## 全程禁止事项

- 不修改或覆盖 D2-A-E001/R3/E002/T001/E003/R4 冻结结果。
- 不在单 seed/旧开发数据上宣称跨 seed 或盲测泛化。
- 不因历史教师门失败就未经新审计将教师分数当真值；不将失败的学生用复杂 KD 损失掩盖。
- 不同时训练模型，不静默回退 CPU，不提交大型可重建缓存、用户本地 GMTI 包。
- 不修改生产 GMTI 链。
